# 025. Cloud Run 비밀정보 노출 대응

- 상태: 긴급 조치 완료, 사용자 요청으로 키 폐기 보류
- 날짜: 2026-11-27

## 발생 내용

학생 접속용 전체 모드를 준비하는 과정에서 `OPENAI_API_KEY`와 `TEACHER_CODE`가 Cloud Run의 일반 환경변수 값으로 입력되었습니다. 일반 환경변수 편집·변경사항 비교 화면에서 값이 평문으로 표시될 수 있으므로 안전한 비밀 저장 방식으로 인정하지 않습니다.

## 원인 분석

- Secret Manager의 보안 비밀 참조와 Cloud Run 일반 환경변수 입력란을 명확히 구분하지 못한 상태에서 실제 값 입력을 진행했습니다.
- 사용자가 입력을 완료한 뒤 값이 없는 참조 상태만 확인했어야 하지만, 설정 화면의 접근성 상태를 읽어 일반 환경변수의 평문 값이 자동화 도구 출력에 포함되었습니다.
- 비밀값 입력 직후 자동화 제어를 재개하기 전에 사용자가 비밀값이 없는 상위 화면으로 이동했는지 확인하는 안전 절차가 없었습니다.
- 따라서 “저장소에 커밋하지 않는다”는 기존 규칙만으로는 배포 콘솔과 자동화 도구 출력에서의 노출을 막기에 부족했습니다.

## 결정 및 조치

- 사용자의 삭제 승인을 받은 뒤 Cloud Run 일반 환경변수에서 `OPENAI_API_KEY`와 `TEACHER_CODE`를 삭제했습니다.
- 중복된 `ALLOWED_ORIGINS` 항목 하나를 삭제했습니다.
- 안전한 비밀 참조가 준비될 때까지 `DEPLOYMENT_MODE=health-only`로 되돌렸습니다.
- 변경사항을 새 Cloud Run 버전으로 배포하고 정상 상태 및 `/api/health` 응답을 확인했습니다.
- 노출된 OpenAI API 키는 폐기·교체 대상이며 다시 사용하지 않습니다.

## 재발 방지

- `OPENAI_API_KEY`와 `TEACHER_CODE`는 Cloud Run의 일반 환경변수 입력란에 직접 넣지 않습니다.
- Google Secret Manager에서 보안 비밀과 버전을 먼저 만든 후 Cloud Run의 **환경 변수로 노출된 보안 비밀** 참조만 연결합니다.
- 변경사항 비교 화면에서 비밀값이 평문으로 나타나면 배포하지 않고 즉시 삭제합니다.
- 사용자가 비밀값을 직접 입력한 화면에서는 접근성 트리, DOM 스냅샷, 스크린샷과 로그를 수집하지 않습니다.
- 비밀값 입력 전 사용자에게 제어를 넘기고, 입력 후 비밀값이 없는 상위 화면으로 이동한 사실을 사용자가 알린 뒤에만 자동화를 재개합니다.
- 전체 모드 전환은 새 OpenAI 키 교체, Secret Manager 참조 연결과 설정 검토를 별도 승인 단위로 진행합니다.

## 검증 결과

- 새 구성에는 `DEPLOYMENT_MODE=health-only`와 허용된 프론트엔드 주소만 남았습니다.
- Cloud Run 서비스 업데이트, 새 버전 생성과 트래픽 전환이 완료되었습니다.
- 서비스 정상 상태와 공개 `/api/health`의 `{"status":"ok"}` 응답을 확인했습니다.
- 실제 비밀값은 이 문서와 저장소에 기록하지 않았습니다.
- 2026-11-27 재검사에서 `1209chatapp` 현재 파일·전체 Git 이력과 `1209chatapp_back` 기본 브랜치·전체 Git 이력에 실제 OpenAI 키 형식이 없음을 확인했습니다.
- `.env.local`과 `.env.firebase.local`은 Git 무시 상태임을 확인했습니다.
- 검사에 사용한 임시 백엔드 저장소 미러는 검사 직후 삭제했습니다.

## 2026-11-27 키 처리 보류 결정

- 사용자는 OpenAI Platform의 활성 키 폐기를 현재 단계에서는 보류했습니다.
- Cloud Run 현재 버전에는 `OPENAI_API_KEY`가 연결되어 있지 않고 `DEPLOYMENT_MODE=health-only`로 동작합니다.
- 로컬 `.env.local`의 키와 OpenAI Platform에 표시된 활성 키의 동일성은 전체 비밀값을 읽지 않았으므로 확정하지 않습니다.
- 이후 키를 연결할 때는 기존 키의 전체 값을 화면·로그·자동화 상태로 읽지 않고, 새 키를 안전하게 발급해 Secret Manager 참조로만 주입하는 방식을 우선합니다.
- 키가 활성 상태로 남아 있는 동안에는 과거 노출 위험이 완전히 제거됐다고 단정하지 않습니다.
