## 1. 웹 애플리케이션의 기본 구조

웹은 사용자, 프론트엔드, 백엔드가 서로 통신하는 구조로 설명됩니다.

### 프론트엔드

사용자가 직접 보고 상호작용하는 부분입니다.

- HTML: 페이지의 뼈대와 구조
- CSS: 색상, 글꼴과 레이아웃
- JavaScript: 동적 기능과 사용자 상호작용

### 백엔드

사용자에게 직접 보이지 않지만 서버에서 다음 처리를 담당합니다.

1. 회원가입과 로그인
2. 이전 기록 불러오기
3. 새로운 기록 저장
4. 외부 API 연결
5. 데이터베이스 연결

### 현재 프로젝트 적용

- `App/Web`: 학생·교사용 화면과 상호작용
- `App/Api`: 로그인, 실시간 채팅, 기록 저장, OpenAI API와 파일 처리
- 프론트엔드는 비밀키를 직접 보유하지 않음
- 백엔드가 모둠 권한과 타이머 종료를 최종 판정

## 2. 개발 도구와 프론트엔드 방식

### Git과 GitHub

- Git은 코드 변경 이력을 기록하는 버전 관리 시스템입니다.
- GitHub는 Git 저장소를 온라인에서 관리하는 서비스입니다.
- 초기 사용자 이름과 이메일 설정 예시가 제시됩니다.

현재 프로젝트에서는 아직 GitHub 연결을 자동으로 수행하지 않습니다. 실제 환경변수와 비밀키는 원격 저장소에 올리지 않습니다.

### Node.js와 Vite

- Node.js는 프론트엔드 개발 도구 실행에 사용됩니다.
- Vite는 프로젝트 생성, 개발 서버, 파일 변경 반영과 배포용 빌드를 돕습니다.

### Vanilla JavaScript

- 브라우저가 기본 제공하는 JavaScript로 웹앱을 만드는 방식입니다.
- 초기 구조를 파악하기 쉽고 빌드 복잡도가 낮습니다.
- 프로젝트가 커지면 React 또는 Vue 같은 도구로 확장할 수 있습니다.

### 현재 프로젝트 적용

1시간 교실 시연 MVP는 Vanilla JavaScript를 사용합니다. 실시간 채팅과 상태 관리가 더 복잡해져 유지보수 부담이 커질 경우에만 프레임워크 전환을 검토합니다.

## 3. 프로젝트 문서와 단계별 작업

자료에서 제시한 초기 구조는 다음과 같습니다.

```text
Project/
├─ App/
│  └─ Web/
├─ AGENTS.md
└─ Develop.md
```

핵심 원칙은 다음과 같습니다.

- 프로젝트 구조를 먼저 만듭니다.
- `AGENTS.md`에 작업 매뉴얼을 둡니다.
- `Develop.md`에 사용자와 합의한 설계를 누적합니다.
- AI가 만든 구조와 결과물을 사람이 확인합니다.
- 웹앱 전체를 한 번에 만들지 않고 작은 단위로 나누어 검증합니다.
- 개발 토큰 사용을 고려해 필요한 수준의 모델을 선택합니다.

### 현재 프로젝트 적용

현재 저장소는 프론트엔드와 백엔드를 분리하고 설계 인터뷰, 결정, 요구사항과 조사 문서를 별도 관리합니다.

## 4. Deep Interview를 이용한 설계

참고자료는 구현 전에 다음 항목을 인터뷰로 결정하도록 안내합니다.

- 챗봇의 사용 목적과 대상
- 챗봇 인터페이스 구성
- 구현 방식
- OpenAI API 호출
- 데이터베이스 저장

### 현재 프로젝트에서 확정된 내용

- 대상: 초등학교 5~6학년
- 교사: 활동과 모둠방을 관리하는 관찰형 관리자
- 학생: 1~6모둠에 등록하고 실시간 협업
- 화면: 교사 안내, 실시간 채팅, 역할 기반 작업 기록의 3분할
- AI: 작업 기록과 과정 피드백 초안을 제안하되 학생 또는 교사 확인 필요

## 5. OpenAI API

### API 개념

API는 서로 다른 소프트웨어 구성요소가 정해진 방식으로 통신하게 하는 메커니즘입니다.

### 공식 문서와 Responses API

- API는 빠르게 변하므로 최신 사용법은 공식 문서를 확인합니다.
- 응답 생성은 Responses API를 기준으로 검토합니다.
- Agents API도 사용할 수 있지만 참고 실습에서는 적극적으로 사용하지 않습니다.

### API 키와 사용량

- 키는 생성 직후 안전하게 보관합니다.
- API Dashboard에서 키와 사용량을 관리합니다.
- 키는 `.env` 계열의 로컬 환경파일 또는 배포 플랫폼 비밀 설정에 둡니다.
- 프롬프트와 실제 API 호출 위치를 직접 확인합니다.

### 현재 프로젝트 적용

- `OPENAI_API_KEY`는 `.env.local`에 저장하고 Git에서 제외합니다.
- OpenAI API는 `App/Api`에서만 호출합니다.
- 전체 채팅을 매번 보내지 않고 확정 작업 기록과 최근 관련 대화만 전달합니다.
- 학생 메시지마다 자동 호출하지 않습니다.
- 모델과 응답 길이는 환경변수와 서버 상한으로 관리합니다.

## 6. Firebase와 Firestore

Firebase는 웹 애플리케이션을 위한 개발 플랫폼이며 Firestore는 문서형 데이터베이스입니다.

### 기본 구조

```text
컬렉션
└─ 문서
   └─ 필드
```

### 설정 흐름

1. Firebase 프로젝트 생성
2. 프로젝트 이름 지정
3. Firestore 데이터베이스 생성
4. 위치와 운영 모드 선택
5. 웹앱 등록과 SDK 설정 확인
6. 컬렉션과 문서 구조 설계
7. 보안 규칙 작성
8. 실제 저장 결과 확인

### 중요 보안 원칙

Firestore는 보안 규칙이 없거나 잘못되면 저장이 실패하거나 데이터가 과도하게 공개될 수 있습니다. 연결 코드와 보안 규칙을 함께 설계하고 테스트해야 합니다.

### 현재 프로젝트 적용 판단

- 1시간 로컬 MVP는 설치와 검증 속도를 위해 SQLite를 사용합니다.
- 여러 학급에서 운영하거나 클라우드 배포할 때 Firestore 전환을 검토합니다.
- 전환 시 활동, 학생, 메시지, 작업 기록, 질문, 의견, 파일 메타데이터를 별도 컬렉션으로 설계합니다.
- 학생은 다른 모둠 데이터에 접근할 수 없고 교사는 담당 활동만 열람하도록 보안 규칙을 작성합니다.
